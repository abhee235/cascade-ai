# Cascade Eval — task fixtures (PLAN-eval E2)

Tier-1 smoke suite: 10 small, **dependency-free** tasks (plain Node, checked with `node --test` — no
`npm install`, no network) that a Cascade session must solve end-to-end. Categories map to the harness
subsystems they stress (see `docs/PLAN-eval.md` for the failure→knob routing table).

## Fixture layout

```
eval/tasks/<id>/
  task.json     # spec (below)
  repo/         # seed project — copied to a temp dir per run; NEVER mutated in place
  solution/     # hand-made fix, overlaid onto repo/ by verify-fixtures to prove the check is solvable
```

## task.json spec

```jsonc
{
  "id": "edit-rename-function",
  "tags": ["edit"],                  // edit | feature | fix | search | longctx
  "prompt": "…what the agent is asked to do…",
  "check": "node --test",     // run in the working copy; exit 0 = solved
  "budgets": { "maxTurns": 12, "timeoutMs": 300000 },
  "protected": ["tests"],            // paths the runner RESTORES from the fixture before running check —
                                     // an agent that edits the tests instead of the code can't game the score
  "session": { "contextWindow": 8192 } // optional overrides (longctx tasks pin a small window so
                                       // compaction pressure is guaranteed on any model)
}
```

Rules:
- **Checks are behavioural** (run the tests) — never diff/string matching (see PLAN-eval "no reward hacking").
- **Every fixture must fail on the seed and pass on the solution** — enforced by `node eval/verify-fixtures.mjs`
  (run it after adding/changing any fixture).
- Keep repos tiny; the two `longctx-*` fixtures use bulk files generated by `tasks/_generate-longctx.mjs`
  (committed output; re-run the script if you change it).

## The 10 tasks

| id | tags | stresses |
|---|---|---|
| edit-rename-function | edit | exact-string Edit reliability, replace-all across one file |
| edit-fix-pagination | edit | reason-from-symptom → one-line fix |
| feature-add-command | feature | new file + registration edit (multi-file, follow the pattern) |
| feature-stats-module | feature | create module + integrate into an existing one |
| fix-format-duration | fix | run tests → read failure → fix code (tests protected) |
| fix-empty-cart | fix | crash on empty input; two functions to harden |
| search-retry-default | search | find a buried default through layers of files |
| search-negative-amount | search | locate the right throw among decoys; change behaviour |
| longctx-wire-modules | longctx | needles across 4 large files; 8k window forces compaction |
| longctx-changelog-version | longctx | synthesize facts from big docs into code |
| delegate-scatter | delegate,longctx | 6 big files vs 8k window — delegation is the winning strategy; prompt stays NEUTRAL (we measure `subagentCalls`, we don't instruct delegation) |
